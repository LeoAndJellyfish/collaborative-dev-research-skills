# 合作式研究

## 确认研究路线

1. 阅读研究问题、已有协议、结果与路线图，核对结论对应的证据。为各阶段写明待回答的问题、可能的解释、所需证据、阶段产物，以及结果将怎样决定下一步。
2. 实验或复现应在测量前记录数据来源与版本、样本单位与划分、指标及分母、基线与对照、关键参数、达标与停止条件。复现时说明与原协议的差异。文献或定性研究可对应记录来源、纳入规则、核查方式与收束条件。用简短说明交代重要选择所排查的解释、误差来源或资源约束。
3. 初次执行前，请用户确认路线。已有明确批准的路线或用户指定按现有路线继续时，核对相应阶段并从该处推进。研究问题、主要口径、样本范围、关键门槛或显著成本变化时，先说明影响并确认受影响分支的调整。确认期间可做只读核查、准备草案，并继续其余已获授权且可独立推进的工作。

## 维护路线图

- 在 `README.md` 放置 Mermaid `flowchart TD` 路线图。项目已有权威路线图时，沿用该图并从 README 提供入口。只读任务在回复中交付图或更新建议。
- 节点写明阶段、状态和证据产物。连线展示前置依赖、并行分支与汇合点。用决策节点表示用户确认和证据门槛，分别标明达标后的验证路线与未达标后的复核、调整或收束路线。
- 用文字区分待确认、待办、下一步、进行中、已完成和阻塞。可用绿色标已完成、黄色标下一步及进行中、灰色标待办、红色标阻塞。状态、依赖或结果改变时更新图，并在图旁链接本轮协议、结果及下一步。
- 分开记录执行状态和研究判定。完成测量但未达门槛时，标记测量已完成，保留观测值，并注明后续验证未触发。运行失败或记录缺失时，标明执行问题和待补证据。

## 并行推进与处理阻塞

- 按依赖并行准备数据或文献、实现测量、设计对照和核查协议。明确各线的输入版本、写入范围和交接产物。共享原始数据与协议由单一责任方维护；资源冲突时排队。按宿主能力和现有授权使用并行工具或子代理。
- 确认性测量在样本、协议和判断规则固定后启动。尽量用独立证据检验探索阶段提出的发现。根据结果作出的新分析标为探索，保留原方案及其结果；后续确认另行固定方案。汇总时按实际覆盖范围报告结果、分母、反例及关键配置差异。
- 单线受阻时，记录原因与恢复条件，继续其他可执行分支。若所有已授权分支均受阻，完成可行的诊断与安全重试后停在最近的可复核状态，请用户提供具体决定、资料或权限。请求中列明自上次收到用户消息以来的进展和证据、阻塞点与已尝试办法，以及收到回复后从哪里恢复。

## 阶段整理与交接

- 汇总研究问题、实际观察、解释与适用范围，注明门槛判定和下一步。归档协议版本、输入清单或数据位置、脚本版本、关键环境与复现命令，以及支持结论的原始输出、对照与失败记录。
- 先核对依赖、引用和复现所需文件。按项目约定归置当前协议、分析与结果，归档中间迭代，并清理本轮可重建且已无引用、无人使用的临时文件。更新并核对移动后的引用，记录从哪个输入、版本或检查点继续。
