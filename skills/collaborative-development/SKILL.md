# 合作式开发

## 确认开发路线

1. 阅读项目说明、现有路线图、最近改动与验证记录。核对已有实现和用户已确认的事项，明确本轮目标、约束、阶段产物和可观察的验收条件。
2. 提出路线草案。用简短说明交代关键设计、技术选型和参数为什么适合当前约束，以及选择对兼容性、成本或后续维护的影响。存在实质取舍时，比较可行选项并说明需要用户决定的事项。
3. 初次实施前，请用户确认草案。已有明确批准的路线或用户指定按现有路线继续时，核对所批准的阶段并从该处推进。范围、兼容承诺、验收口径或显著成本变化时，先说明影响并确认受影响分支的调整。确认期间可做只读核查、准备草案，并继续其余已获授权且可独立推进的工作。

## 维护路线图

- 在 `README.md` 放置 Mermaid `flowchart TD` 路线图。项目已有权威路线图时，沿用该图并从 README 提供入口。只读任务在回复中交付图或更新建议。
- 节点写明阶段、状态和交付物。连线展示前置依赖、并行分支和汇合点。用决策节点标出用户确认或技术验收，给每条分支标注触发条件及去向。
- 用文字区分待确认、待办、下一步、进行中、已完成和阻塞。可用绿色标已完成、黄色标下一步及进行中、灰色标待办、红色标阻塞。图旁附本轮证据、当前工作与下一步。
- 在状态、依赖或验收结果变化时更新图与摘要。依据可查的改动、测试结果或其他约定证据确认完成；排队、运行中和待验证的工作保留对应状态。验收未通过时记录失败证据，并标明受影响的后续节点。

## 并行推进与处理阻塞

- 并行安排前置条件已满足、产物可以独立检查的分支。开始前明确各线的输入版本、写入范围、预期产物和验收方式。共享接口先对齐，共享文件指定一个写入者，汇合后验证集成路径。
- 按宿主能力和现有授权组织并行工具调用或子代理工作。资源或写入冲突时安排执行顺序，并在图中区分已经启动和排队的分支。
- 单线受阻时，记录阻塞原因、影响与恢复条件，继续推进其他可执行分支。若所有已授权分支均受阻，完成可行的诊断与安全重试后停在最近的可验证状态，请用户提供具体决定、材料或权限。请求中列明自上次收到用户消息以来的进展和证据、阻塞点与已尝试办法，以及收到回复后从哪里恢复。

## 阶段整理与交接

- 阶段结束时清点交付、活跃任务、验证记录和临时产物。按项目约定将仍在使用的文件归入对应目录，将需要追溯的中间版本归档。记录对应提交或快照、验证证据和恢复入口，更新并核对移动后受影响的引用。
- 清理本轮可重建且已无引用、无人使用的临时文件。归属不明的文件、用户产物和复现所需材料留待核对。
- 在路线图旁记录本阶段的交付与验收结果、未决事项和下一步，给出可直接接续的分支、文件或命令。
